### F64. 지표별 등급 라벨 분리 (완료)

브랜치: `feature/indicator-grade-vocabulary` (백엔드 N40과 같은 PR)

자외선·오존·미세먼지·초미세먼지·통합지수가 전부 같은 어휘(좋음/보통/나쁨)를 썼다.
실기기에서 자외선지수 9가 "나쁨"으로 표기됐는데 기상청 기준으로는 "매우높음"이다.

- [x] `src/lib/air-status.ts`를 지표별로 나눈다 — `AIR_STATUS_*`(4단계) / `UV_LEVEL_*`(5단계). `Record`로 선언해 등급이 늘면 컴파일이 실패하는 성질은 유지
- [x] 색상 단계를 등급 수에 맞춰 늘린다 — 기상청 관례(낮음 녹 · 보통 황 · 높음 주황 · 매우높음 적 · 위험 보라)에 맞춰 주황·보라를 추가하고, 대기질 '매우나쁨'용 진한 적색을 추가
- [x] `weather-detail.tsx`의 게이지 눈금을 지표별 어휘로 바꾼다 — 하드코딩된 `['좋음','보통','나쁨']`을 제거하고 등급 순서 배열(`*_ORDER`)에서 뽑는다
- [x] 홈 카드·상세·기록의 어휘 일치 확인 — `StatusBadge`·`WeatherMetric`·기록 그리드까지 스케일을 판별 유니온으로 받게 바꿔, 지표에 맞지 않는 등급을 넘기면 컴파일이 실패한다

**타입을 갈랐더니 숨어 있던 문제 둘이 드러났다.**

프론트 등급 타입이 손으로 적혀 있어(`AirStatus = 'good'|'moderate'|'bad'`) 서버가 등급을
늘려도 드리프트 검사를 그대로 통과했다. 생성 타입에서 파생하도록 바꿨다.

`status === 'bad'` 비교가 새 등급을 놓쳤다. '매우나쁨'일 때 미세먼지·오존 경고 문구가
사라진다. 컴파일러가 잡을 수 없는 종류라 `isAirConcerning()`으로 묶었다.

완료 기준: 자외선은 낮음~위험, 대기질은 좋음~매우나쁨으로 표기되고, 세 화면의 어휘가 일치한다. → 충족
